# Acceptance check

Mapping of the ten criteria in the kit's `docs/ACCEPTANCE.md` to what this delivery does and how it was verified. "Automated" refers to `tests/` (see TEST_REPORT.md); "manual" refers to checks performed in the browser on Windows 11 during delivery.

| # | Criterion | Status | Evidence |
|---|---|---|---|
| 1 | Install & run on Windows/macOS/Linux without cloud services; one-step or precise, tested steps | **Met on Windows; macOS/Linux by construction** | `python -m nexus --add <folder>` (stdlib only), `run.bat`, `scripts/run.*`, `pip install .` → `nexus`; PyInstaller build via `scripts/build_exe.*` produced and smoke-tested `dist/ProjectNexus/ProjectNexus.exe` (scans, serves UI). macOS/Linux paths are platform-neutral but were not executed here (LIMITATIONS.md). |
| 2 | Scan fixture with Python, React, Rust, monorepo, nested git, empty folder, circular symlink, no-permission folder, Persian name — no crash, no escaping the root; detectable projects shown, minor errors reported | **Met** | `fixtures/make_fixture.py` builds exactly these cases (+ one project per category + a backend/frontend/ai multi-part folder). Automated: `test_scan_completes_without_crash`, `test_every_top_level_folder_is_exactly_one_project` (node count == valid top-level folders on disk, nothing nested), `test_links_are_never_followed`, `test_persian_named_project`, `test_git_status_and_nested_repo` (nested repo reported *inside* its parent), `test_monorepo_is_one_project_with_components`, `test_multi_part_project_components_and_labels`, `test_nested_mode_lists_candidates_and_promotion_makes_nodes`; empty and unreadable folders are listed as *skipped* with a reason in the scan summary and in Settings. |
| 3 | Data correctness: file count, language, manifest, Git state, mtime match the fixture; status & category shown with evidence; no fake UI data | **Met** | `test_file_counts_match_disk`, `test_languages_and_manifests`, `test_last_modified_matches_newest_file`, `test_git_status_and_nested_repo`, `test_every_category_has_evidence`. UI shows *Evidence* (status signals, detection reason, per-category rule evidence with "rule confidence — not a quality score"); the reference image's "Project Health 82 %" panel was deliberately **not** reproduced. |
| 4 | Graph inspired by the reference: glowing centre, orbits, coloured labelled nodes, links, three-column panel; slow default rotation, stop, reduced motion, zoom/pan/focus, select, 2D/3D, search and filter really work | **Met** | Canvas renderer (`nexus/static/js/universe/*`): hub crystal with rings and glow, orbital rings sized to the node count, one full-size shaded crystal per top-level folder coloured by primary category (secondary categories as beads, status dot), curved links, collision-free labels that shrink before they disappear, fit-to-view on load. Rotation ≈ 1 turn / 240 s (configurable), Rotate toggle, `prefers-reduced-motion` + setting, drag pan / d-pad, wheel & pinch zoom, Focus/Reset, click/tap/double-click/keyboard select, 3D (perspective) and 2D (orthographic) modes with a smooth transition and persisted choice, search suggestions with ↑/↓ + Enter that fly the camera to the project, non-matching nodes fade, status/category/language filter chips. **Focus view:** camera glides to the selected folder, rotation pauses, other nodes step back, up to 8 internal parts (components, README, manifests, entry points, deployment files) orbit it as satellites, breadcrumb *Workspace › Project › part* and *Back to workspace* return. Screenshots in `docs/screenshots/` (1440×900 3D/2D/focus, 768×1024, 375×812, reduced motion). |
| 5 | Accessibility: all projects also in a text list; keyboard-operable controls with visible focus and accessible names; responsive at 375/768/1440 without losing core functions | **Met** | *Projects* view table + in-graph *Text list* overlay; canvas is focusable with arrow-key navigation, Enter/Esc, +/−, R, 0, F, L; `aria-live` announcements; every icon button has `aria-label`; `:focus-visible` outline on all controls; contrast tokens ≥ AA on dark and light. Layouts verified manually at 375 (bottom nav + sheet), 768 (icon sidebar + drawer) and 1440 (three columns). |
| 6 | Works fully without Ollama; with a local model only after opt-in, valid suggestions; broken/timeout responses don't break the UI; README prompt injection cannot run commands or change config; secrets never reach the model | **Met** | `test_disabled_by_default_and_consent_required`, `test_suggestion_roundtrip_with_mock_model`, `test_timeout_and_bad_json_do_not_break`, `test_injected_instructions_in_model_output_are_inert`, `test_payload_excludes_secrets_and_caps`, `test_readme_description_and_injection_is_data`, `test_api_ai_endpoints`. A real Ollama round-trip was **not** run in this delivery (no Ollama installed); the provider code path is exercised with a mocked HTTP layer. |
| 7 | Persistence across rescan and restart: workspaces, manual overrides, settings, data; deleted/moved projects handled clearly | **Met** | SQLite + `settings.json` in the data dir; `test_override_survives_rescan_and_missing_project_lifecycle` (override kept, project → *Missing* tombstone, reappears with override), `test_settings_persist_and_recover`, `test_database_migrates_and_is_idempotent`, `test_v1_database_drops_nested_projects_and_requests_a_rescan` (upgrade from the old nested model keeps top-level overrides and rescans automatically); restart verified manually (server restarted against the same data dir after the upgrade). |
| 8 | Security: cross-origin cannot change settings/scan; symlinks outward not read; no writing/executing project files; loopback only unless chosen | **Met** | `test_mutations_require_token`, `test_cross_origin_requests_are_rejected`, `test_dns_rebinding_host_check`, `test_static_traversal_blocked`, `test_ids_are_validated`, `test_links_are_never_followed`; CLI refuses non-loopback without `--allow-remote`. Details in SECURITY.md. |
| 9 | ≥200 projects: UI stays interactive; scan has progress and cancel; graph not blocked during scan; results and environment recorded | **Met** | `test_scan_and_query_240_projects` → `tests/perf_report.json` (258 projects: full scan ≈1.0–1.3 s, incremental 0.45 s, list 14 ms). Browser: 309 projects rendered with category clustering; synchronous frame cost median 15.9 ms / p90 30 ms (309 nodes) and 5.4 ms (41 nodes) at 846×814 CSS px, Chromium in the desktop app; scan runs on a worker thread with polling progress + cancel while the graph keeps animating. See TEST_REPORT.md. |
| 10 | Delivery: full source, quick-start README, model setup guide, sample data, targeted tests, build/test report, explicit remaining limitations | **Met** | This repository; README.md (FA/EN), docs/INSTALL.md, docs/AI_SETUP.md, fixtures/make_fixture.py, tests/, docs/TEST_REPORT.md, docs/LIMITATIONS.md. |
